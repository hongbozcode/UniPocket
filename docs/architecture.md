# 架构方向

## 当前约束

首版 Flutter + Dart、Android 优先，使用本地数据库和文件持久化，首次安装即能离线运行。业务规则与存储实现分离，页面通过有实际业务意义的模块操作完成工作，存储细节集中封装。

后续接入后端是演进目标，不代表首版需要远程空实现、账号体系、同步引擎、通用多源仓储框架或仅转发的分层。按实际行为划分学习管理、导入、随机工具、备份恢复和系统提醒等职责，不为每个页面机械创建完整层级。

## 技术方向与候选

以下保留已有技术意向，不代表依赖版本、兼容性或授权已验证。引入依赖前遵循仓库 Context7 文档规则核实。

| 方面 | 基础方向或候选 | 当前地位 |
| --- | --- | --- |
| 应用框架 | Flutter + Dart | 产品指定方向 |
| UI | Material 3 | 基础组件方向；配色、排版、材质与动效遵循[视觉规范](product/design.md) |
| 状态管理 | Riverpod | 原有推荐，实施前核实 |
| 导航 | go_router | 原有推荐，实施前核实 |
| 结构化持久化 | SQLite，候选 Drift | 本地方向；具体集成待设计 |
| 文件 | App 私有目录及用户主动导出 | 首版备份文件；未来再支持媒体资产 |
| 本地提醒 | flutter_local_notifications | 原有候选；需真机验证 |
| 组织方式 | 模块化 MVVM + Repository | 参考，不机械堆层，以已确认的简洁性约束为准 |

课程、任务、倒计时、提醒配置、随机列表及抽取进度、用户设置需持久化。备份恢复保持领域关系一致，失败不能损坏当前数据。具体表结构和迁移机制在实施中设计，不能由未来同步需求推导出尚未确定的数据协议。

未来图片和扫描文件可存私有目录并保存路径元数据；Dart image、OpenCV／扫描 SDK、本地分割模型、pdf + printing 均仅为后续候选。是否本地、后端或混合处理仍待决定，首版不安装这些依赖。

## 后续后端

课程接入后端已在规划中，但同步、备份、解析、账户归属、冲突解决及接口协议尚未确定。把这些问题作为后续设计输入，不把“可接后端”解释为只替换数据库即可完成同步。

## 验证原则

已确认主要从应用用户操作到持久化结果测试完整行为，优先真实本地数据库；仅在时钟、随机源、系统通知等外部依赖处控制环境，并补充 Android 真机通知验证。详细验收与测试决定见[首版规格](../.scratch/unipocket-v1/spec.md)。
