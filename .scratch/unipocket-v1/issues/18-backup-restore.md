# 18: 完整本地备份与覆盖恢复

**What to build:** 用户主动导出全部本地数据，并在干净安装中安全覆盖恢复、重建未来提醒。

**Blocked by:** 08: 有效课程提醒；09: 倒计时事件提醒；15: 工具发现与首页常用入口

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 备份覆盖全部学期、课程和安排、调停课及独立补课、DDL、倒计时、提醒配置、工具列表、未完成轮次和应用设置，包括收藏及最近使用。
- [ ] 只做完整导出和覆盖恢复，不做数据合并或自动备份；核心数据不主动上传。
- [ ] 恢复前校验文件，再明确提示覆盖并要求确认；取消、无效文件或恢复失败不损坏当前数据。
- [ ] 干净安装恢复后关系和轮次一致，重启后仍可继续使用。
- [ ] 成功恢复后按有效数据重建未来提醒，不补发过去提醒；系统权限使用当前手机实际状态，不恢复旧设备权限。
- [ ] 导出和恢复有清晰进度与结果反馈；真实数据库验证失败完整性，并在 Android 上验证文件操作和恢复后提醒。
- [ ] 不以任务 17 为前置；先用手动录入的完整领域数据验证，真实导入数据的迁移联验由任务 19 完成。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
