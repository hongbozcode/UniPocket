# 03: 学习任务完整管理

**What to build:** 用户从首页及课表页进入学习任务，管理独立或关联课程的 DDL，持续看见逾期未完成事项。

**Blocked by:** 02: 手动录课与今日／周课表

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 创建、编辑、删除带标题、截止日期时间、备注及可选课程的 DDL；仅选择日期时明确显示默认 23:59，并允许修改。
- [ ] 支持完成和撤销完成；逾期由校园时间计算，逾期未完成任务继续可见，不自动完成。
- [ ] 首页展示未完成任务并醒目标识逾期，状态不只靠颜色；提供快捷创建、空状态引导及任务较多时可达的完整列表。
- [ ] 支持按课程及状态筛选，并以逾期、今天、接下来组织任务展示。
- [ ] 通过真实数据库验证独立任务、课程关联、编辑删除、完成撤销和截止边界，重启后保留；系统提醒由任务 07 交付。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
