# 19: Android 首版完整试用与发布验收

**What to build:** 在约定 Android 真机上验证完整首版试用流程，提供可追溯的验收结果和发布判断。

**Blocked by:** 17: 真实学校 XLSX 导入与重复导入验证；18: 完整本地备份与覆盖恢复

**Status:** ready-for-agent

**External prerequisite:** 发布验证前需确定 Android 验收真机。

## Acceptance criteria

- [ ] 确定验收 Android 真机，记录机型、系统和应用版本；逐项核对首版 67 条用户故事的行为与证据。
- [ ] 串联验证首次安装无账号断网使用、重启持久化、学期切换、调停课、DDL、倒计时及六项随机工具。
- [ ] 用真实学校样例完成导入、纠错、排除、重复跳过、冲突确认及失败完整性验证；将真实导入数据导出并在干净安装中恢复。
- [ ] 真机验证通知实际送达、权限关闭不阻断管理、变更后更新及恢复后未来提醒重建；模拟通知成功不能替代真机结果。
- [ ] 检查数据不主动上传的行为与隐私说明、耗时操作反馈及性能表现，不虚构性能阈值或最低系统版本。
- [ ] 核对四入口、首页顺序、关键空状态和确认流程；检查窄屏、长文本、文本缩放、安全区域、滚动及状态可理解性。
- [ ] 记录检查对象、方式、证据、失败和未验证项；缺真实样例或真机通知证据时不得宣布整版验收完成，历史 HTML 证据不能代替 Android 验收。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
