# 14: 随机分组

**What to build:** 用户保存独立分组名单，按组数或每组人数上限得到均衡分组。

**Blocked by:** 01: 从零建立 Flutter 应用，打通离线学期配置

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 提供工具页入口，分组名单可命名保存和编辑，同名成员独立保留并可用学号或备注区分，不跨工具共享。
- [ ] 按组数分组时各组人数最多差 1；按人数上限分组时尽量均衡，10 人上限 4 人得到 4／3／3。
- [ ] 先随机打乱再分配，每位成员恰好出现一次，不引入指定同组或避开同组功能。
- [ ] 名单及参数无效有明确反馈；完成后姓名标签水平且完整可读，大名单可滚动查看。
- [ ] 简化反馈中避免重复触发，完成或取消清理临时状态；真实数据库验证名单重启保留，可控随机源验证成员完整性及人数边界。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
