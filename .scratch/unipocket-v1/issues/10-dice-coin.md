# 10: 掷骰子与抛硬币

**What to build:** 用户从工具页投掷单个六面骰或抛一枚硬币，得到清晰一致的随机结果。

**Blocked by:** 01: 从零建立 Flutter 应用，打通离线学期配置

**Status:** ready-for-agent

## Acceptance criteria

- [x] 提供可用工具入口，单个六面骰六面及硬币两面等概率，无隐藏权重或指定结果。
- [x] 具备操作前、进行中和结果状态；采用 Android 简化反馈，骰面或币面与最终文字一致。
- [x] 进行中防止重复触发，返回取消后清除临时状态；不保存骰子和硬币结果历史。
- [x] 控制随机源验证候选范围及结果一致性，不用一次随机频率断言宣称公平。
- [x] 窄屏、长文案及文本放大不遮挡结果或主操作。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
