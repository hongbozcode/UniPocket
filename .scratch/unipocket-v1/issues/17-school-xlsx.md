# 17: 真实学校 XLSX 导入与重复导入验证

**What to build:** 适配用户学校一种真实 XLSX 格式，让用户选择文件、预览纠错并安全导入，重复导入不制造相同安排。

**Blocked by:** 16: 导入候选结果的预览、纠错与原子提交

**Status:** needs-info

**External blocker:** 用户已提供首个学校样例，位于本地 `class_schedule_template/Hebei Normal University of Science & Technology/`，包含 `xskb.xlsx` 与 `效果示例.jpg`。目前仅确认文件存在；格式分析、必要字段含义、课程身份及精确去重规则尚未确认。任务 16 已交付，真实文件接入与学校适配仍由本任务完成，并继续作为任务 19 整版验收的前置条件。

## Acceptance criteria

- [ ] 取得用户学校真实 XLSX 样例及必要字段含义确认；据此补齐课程身份识别、表头与合并单元格解析、候选行定位及精确去重规则后，方可转为 ready-for-agent。
- [ ] 使用学校实际导出文件，不要求用户先改为自定义模板；不臆造学校名称、课程编号或宣称任意 XLSX 均可识别。
- [ ] 真实文件解析接入任务 16 的目标学期、预览、逐项错误、修正／排除及一次保存流程。
- [ ] 完全重复的安排默认跳过，重复与时间冲突分别呈现；再次导入同一真实文件不制造相同安排。
- [ ] 用真实样例验证解析与持久化；在保留真实格式依据的前提下补充错误场景，验证取消、失败无部分写入及原数据完整性。
- [ ] 在 Android 上验证真实文件选择、导入进度和结果；未取得样例不得用测试候选或虚构模板宣布学校适配完成。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
