# 07: DDL 提醒与通知权限反馈

**What to build:** 用户获得可配置的 DDL 本地提醒，并能区分数据保存结果与当前设备通知可用状态。

**Blocked by:** 03: 学习任务完整管理

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 接通 Android 本地通知能力；DDL 默认提前 1 天，每项一个提醒，可修改或关闭。
- [ ] 编辑、完成、撤销完成及删除 DDL 后正确更新未来提醒；提醒时间已过明确提示且不补发。
- [ ] 显示当前设备实际通知状态，关闭权限不阻断数据管理，并提供系统设置入口。
- [ ] 保存成功与提醒启用分开表达，不承诺任何设备状态下必然准时送达。
- [ ] 可控时钟及通知边界配合真实数据库验证调度结果；在 Android 真机验证实际送达、权限关闭和设置入口，记录证据与限制。
- [ ] 为后续课程和倒计时接入保留实际可复用的通知能力，不建立无用途的通用平台框架。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
