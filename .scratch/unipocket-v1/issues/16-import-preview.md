# 16: 导入候选结果的预览、纠错与原子提交

**What to build:** 针对已经解析的候选课程和安排，用户预览、纠错、排除并确认后一次保存到目标学期。

**Blocked by:** 02: 手动录课与今日／周课表

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 可选择目标学期，逐项查看候选结果和错误，修正或排除错误项后再确认；未解决且未排除的错误不能被静默保存。
- [ ] 时间冲突单独展示并由用户确认；预留表达重复识别结果的行为边界，不自行确定学校精确去重键。
- [ ] 确认后一次保存选中内容；取消或写入失败不留下部分导入数据，原有数据保持完整。
- [ ] 解析结果加载及提交期间有明确进度、进行中及失败反馈，防止重复提交。
- [ ] 用明确标注的测试候选数据验证预览到真实数据库的完整流程和事务失败回滚，不把虚构模板当学校适配证据。
- [ ] 不确定学校表头、课程身份、合并单元格、候选行定位或精确去重规则；真实文件入口及学校适配由任务 17 完成。

## 实施与验收约束

- 范围与行为以已确认的首版规格为准，使用领域词汇表术语；技术候选不视为已安装或验证。
- 复用现有视觉规范、效果图、HTML 样板参考及资源；所属流程缺少的表单、空状态、错误和确认状态随本任务补齐。Android 首版使用简化反馈，复杂动效及手册重建不进入本任务。
- 验证以用户操作到真实本地数据库的完整行为为主，仅在时钟、随机源、系统通知等外部边界控制环境；关键界面补充集成验证，通知另做真机检查。
- 按变更影响检查窄屏、长文本、文本缩放、安全区域和滚动可达性；记录实际运行证据及未验证项，HTML 截图不代表 Android 行为已实现。
- Status 是 triage 分类，不是执行完成状态；依赖任务完成后才进入可执行前沿。
