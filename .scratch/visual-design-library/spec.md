# 统一视觉规范与设计资源手册

Status: ready-for-agent

交付情况：两版设计手册、独立资源库及六项随机工具的交互动效演示已提供；已验证内容及待验证限制见文末检查记录。Status 表示规格可执行，交付和验收情况分别记录。

## Problem Statement

建立手册前，核心效果图、HTML 样板、运行截图、图标及纸感素材入口分散，早期视觉说明与样板参数存在冲突。手册需要让用户和后续 AI 迅速判断有效版本、找到页面依据并复用统一规则。

## Solution

以视觉规范为 AI 入口，配套 HTML 设计手册。两版按“效果图 → HTML 样板运行截图与交互说明 → 设计资源 → 设计规范”组织，用同一份资源清单关联 12 个页面、9 张当前效果图、运行证据和素材。将规范挂入代理入口，统一后续页面设计流程。

## User Stories

1. As an 产品负责人, I want 通过统一入口浏览全部当前效果图, so that 能迅速理解当前设计方向。
2. As an 产品负责人, I want 每页只展示当前采用的设计, so that 快速找到有效依据。
3. As an 产品负责人, I want 随机分组采用水平姓名标签, so that 已确认的要求能持续保留。
4. As an 页面设计者, I want 按效果图、样板运行截图与交互说明、资源、规范的顺序查阅, so that 能从方向走到实现细节。
5. As an 页面设计者, I want 每页关联效果图、页面标识和 HTML 运行截图, so that 不必手工猜测文件对应关系。
6. As an 页面设计者, I want 对照效果图和实际运行截图, so that 理解实际排版与视觉方向的关系。
7. As an 页面设计者, I want 查看交互说明并播放当前演示, so that 能理解工具动作与页面反馈。
8. As an 页面设计者, I want 区分静态截图和完整动画, so that 不把截图误认为动画已验证。
9. As an 页面设计者, I want 按分类和名称搜索素材, so that 能快速找到可复用内容。
10. As an 页面设计者, I want 查看和下载独立 SVG 图标, so that 后续页面保持统一图标语言。
11. As an 页面设计者, I want 复用透明贴纸和场景插画, so that 页面趣味感保持一致。
12. As an 页面设计者, I want 查看真实纸纹、撕纸和胶带效果, so that 能正确组合通用材质。
13. As an 页面设计者, I want 知道材质组合的限制, so that 避免装饰层相互覆盖。
14. As an 页面设计者, I want 读取独立保存的颜色与尺寸变量, so that 避免旧值混入新设计。
15. As an 页面设计者, I want 查到六项随机工具的动作参考和结果要求, so that 区分展示方案与首版应用要求。
16. As an 页面设计者, I want 查到取消操作与结果提交的规则, so that 操作不会错误消耗轮次。
17. As an 后续 AI, I want 代理入口明确要求读取视觉规范, so that 页面修改遵循统一依据。
18. As an 后续 AI, I want 明确业务规格与视觉规范各自的职责, so that 不因视觉整理扩大首版范围。
19. As an 后续 AI, I want 识别样板尚未实现的状态, so that 不把演示入口当成正式能力。
20. As an 维护者, I want 两版由同一资源清单生成, so that 更新页面时不遗漏另一份索引。
21. As an 维护者, I want 自动检查独立资源路径, so that 不依赖外部 HTML 样板源码也能使用设计资料。
22. As an 维护者, I want 当前素材和对应提示词集中存放, so that 设计资源可独立查阅与复用。
23. As an 手册阅读者, I want 在窄屏浏览和用键盘关闭预览, so that 不同设备与输入方式均可查阅。
24. As an 产品负责人, I want 区分 HTML 截图与 Android 产品状态, so that 正确判断项目完成度。

## Implementation Decisions

- 视觉规范提供 AI 文档版，HTML 手册提供可视化查阅；复用既有设计和素材。
- 资源清单集中维护页面、当前效果图、所采用的截图、规则及 HTML 动效参考；图标、插画、材质及颜色变量从实际文件读取。六项随机工具展示现行独立演示截图，六个基础页面保留尚无新版替代的原样板截图并标明历史来源。
- 两版通过同一构建入口同步。HTML 输出包含实际内容，不依赖运行时获取清单，可直接以本地文件打开。
- 可视化版包含四章节导航、原图放大、页面筛选与搜索、图稿对照、六项工具的动效播放、素材筛选／搜索／下载及变量展示；动作从当前演示查阅。
- 效果图、提示词、图标、插画、材质、视觉变量与运行截图集中存放。分组唯一当前稿使用水平姓名标签。
- 六项工具的独立演示源码随手册维护，支持在手册弹窗播放或从 motion.html 独立打开；默认列表可编辑，状态仅在演示会话内保存。原完整应用样板源码不纳入仓库。
- HTML 完整动作作为展示参考，正式应用的结果与轮次遵循首版规格及视觉规范中的状态反馈；Android 首版采用简化反馈，复杂动画后置。
- 转盘选项只显示用户输入的文字，不按内容推断或绑定图标，默认项和自定义项遵循同一显示规则。
- 代理入口说明触发读取的工作类型、必须执行的复用和交付检查；根文档与首版规格提供统一导航。

## Testing Decisions

- 资料链使用“查页面 → 看效果图与 HTML 截图 → 找素材 → 查规则”；六项随机工具可从页面卡片播放，也可独立打开。
- 沿用现有手册构建检查和浏览器资料链检查，优先验证阅读者从同一手册入口完成查找、对照与获取素材的完整行为。
- 自动验证独立资源存在、两版生成内容同步、页面标识唯一、当前稿引用有效；检查范围见手册维护说明。
- 浏览器从手册验证章节导航、页面／素材筛选与搜索、空结果、放大／对照、截图来源标识、下载入口、键盘关闭及受影响布局；演示变更时检查播放、取消、结果与轮次一致，以及独立入口。
- 好验证面向阅读者能否找到正确资源并完成操作，不锁定内部 DOM 或函数调用顺序。
- 已有样板检查与截图可作视觉方向先例，但不视为新手册已验证，不重复测试未修改的产品业务。

## Out of Scope

- 新增产品页面设计、生图、Figma 写入、Flutter 开发、后端、真实导入或持久化。
- 重写原完整应用样板、扩大首版范围、重新宣称 Android 真机通过。
- 外部部署、素材许可采购、保留原完整应用样板或再建第二套独立动效实现。
